CURSOR INSTRUCTIONS — Frontend Live Candlestick Replay + Docker (Market Data Service)
Project: DayTradingApp-FullStack
Date: 2026-01-22

GOAL
Add a frontend feature that:
1) Lets the user pick a ticker (symbol) from the Market Data Service.
2) Shows historical candles as a candlestick chart + volume.
3) Streams live candle replay over WebSocket (accelerated simulation) and updates the chart in real time.
4) Supports “reset per symbol”: changing ticker closes the current socket, clears chart state, and starts from candle 0 for the new ticker.
5) Works both when running locally and when running via Docker Compose.

BACKEND CONTRACT (ALREADY IMPLEMENTED)
Market Data Service base URLs (host machine):
- HTTP: http://localhost:8000
- WS:   ws://localhost:8000

Endpoints:
- GET /health -> { "status": "ok" }
- GET /symbols?limit=100&prefix=A -> { "symbols": [...], "count": N }
- GET /candles?ticker=AAPL&tf_min=5&limit=200&order=asc -> { "data": [...], "count": N }

WebSocket:
- ws://localhost:8000/ws/replay?ticker=AAPL&tf_min=5&step_seconds=2
Messages:
- STATUS: { type: "STATUS", message: string, ticker: string, tf_min: number, step_seconds: number, total_candles: number }
- CANDLE: { type: "CANDLE", seq: number, candle: Candle }

Candle shape (JSON):
{
  "ticker": "AAPL",
  "tf_min": 5,
  "ts": "2025-08-13T20:55:00",   // ISO string
  "open": 231.07,
  "high": 232.19,
  "low": 230.84,
  "close": 231.18,
  "volume": 2122371,
  "openint": 0
}

FRONTEND TECH CHOICE
Use React + TypeScript.
Use TradingView Lightweight Charts for candlestick + volume.

IMPORTANT: The existing repo already has a frontend in ./frontend/web (see docker-compose). Modify that app rather than creating a new one, unless it is clearly missing React/TS.

A2) Create a typed API client
Create src/api/marketData.ts with:
- Types:
  - Candle
  - CandleResponse { data: Candle[]; count: number }
  - SymbolsResponse { symbols: string[]; count: number }
  - WsStatusMessage, WsCandleMessage, WsMessage union

  - fetchSymbols(limit=100, prefix?:string): Promise<SymbolsResponse>
  - fetchCandles({ ticker, tf_min, limit, order }): Promise<CandleResponse>
  - buildReplayWsUrl({ ticker, tf_min, step_seconds }): string

Implementation notes:
- Use fetch() with proper error handling:
  - non-2xx -> throw Error with response text
- Keep it simple and explicit; no external HTTP client required.

A3) Build a hook that manages: REST bootstrap + WS streaming
Create src/hooks/useMarketReplay.ts:
Inputs:
- ticker: string | null
- tfMin: number (default 5)
- stepSeconds: number (default 2)
- initialLimit: number (default 200)

Behavior:
- When ticker changes:
  1) close any existing websocket
  2) clear candles state and status
  3) fetch initial candles via REST (order asc)
  4) connect websocket replay

- WebSocket message handling:
  - STATUS: set status text (and store metadata)
  - CANDLE: append candle to state (or update last candle if same timestamp)

- Keep a rolling window in state (e.g., last 500 candles) to maintain performance.
- Provide outputs:
  - candles: Candle[]
  - status: string
  - isLoading: boolean
  - error: string | null
  - connect(): void  (optional)
  - disconnect(): void
  - reset(): void (close and re-open from candle 0)

Implementation detail:
- Use a ref for ws: const wsRef = useRef<WebSocket | null>(null)
- Use AbortController for REST fetch on ticker change to avoid race conditions.
- On unmount: always close ws.

A4) Chart component (candles + volume) using lightweight-charts

  - Implement diff using a ref to last timestamp
- Clean up chart on unmount (chart.remove())

Note:

  postgresql://postgres:postgres@postgres:5432/trading

B2) Extend the ROOT docker-compose.yml
Current docker-compose.yml only has frontend/auth/user/mongodb and a single network named “backend”.
Add these services:
1) postgres (TimescaleDB image)
2) pgadmin (optional but recommended)
3) market-data-service

Add volumes section:
  pg_data:

Example additions (adapt naming to existing network “backend”):
- postgres:
  image: timescale/timescaledb:2.14.2-pg16-oss
  container_name: trading_postgres
  environment:
    - POSTGRES_USER=postgres
    - POSTGRES_PASSWORD=postgres
    - POSTGRES_DB=trading
  command: ["postgres", "-c", "shared_preload_libraries=timescaledb"]
  ports:
    - "5433:5432"
  volumes:
    - pg_data:/var/lib/postgresql/data
    - ./db/schema.sql:/docker-entrypoint-initdb.d/01_schema.sql:ro
    - ./db/timescale.sql:/docker-entrypoint-initdb.d/02_timescale.sql:ro
  networks:
    - backend
  restart: unless-stopped

- pgadmin:
  image: dpage/pgadmin4
  container_name: trading_pgadmin
  environment:
    - PGADMIN_DEFAULT_EMAIL=admin@admin.com
    - PGADMIN_DEFAULT_PASSWORD=admin
  ports:
    - "5050:80"
  depends_on:
    - postgres
  networks:
    - backend
  restart: unless-stopped

- market-data-service:
  build:
    context: ./market-data-service
    dockerfile: Dockerfile
  container_name: market-data-service
  environment:
    - DATABASE_URL=postgresql://postgres:postgres@postgres:5432/trading
    # allow frontend origins (hosted at localhost)
    - CORS_ORIGINS=http://localhost:3000,http://localhost:5173
  ports:
    - "8000:8000"
  depends_on:
    - postgres
  networks:
    - backend
  restart: unless-stopped

B3) Timescale init scripts
Create ./db/timescale.sql:
  CREATE EXTENSION IF NOT EXISTS timescaledb;
  SELECT create_hypertable('candles','ts', if_not_exists => TRUE);

IMPORTANT NOTE about init scripts:
- docker-entrypoint-initdb.d scripts run only on first initialization of the data directory.
- If pg_data volume already exists, changes to init scripts won’t re-run automatically.
Dev option to re-init:
  docker compose down -v
  docker compose up --build
